# プロジェクト成功基準

## 一文での成功定義

AIの知識をモデルの重みから切り離し、検証・修正・共有・継承できる持続的な知識基盤を作ること。

モデルが交換されても、知識、経験、評価、関係、出典、修正履歴が失われず、再利用され続ける状態を目指す。

## 成功の本質

成功はPostgreSQLへ大量のデータを保存することではない。次の状態を実現することである。

- WordPress、LLM、SARA、RISA、学習スクリプトが共通のKnowledge Serverを利用できる
- データが出典、生成元、修正者、評価、学習利用履歴、概念、関係、反例まで追跡可能である
- 新しい情報を追加しても、システム全体を再学習せずに利用できる
- 誤った知識を修正すると、以後の利用者へ反映できる
- 同じ知識をLLM、SNN、RISAなど複数のAI方式で共有できる

## 段階別の成功

### 第一段階：データ基盤の分離

```text
AI-data-manager
＝入力・編集UI

Knowledge Server
＝データの正本
```

以下を実現する。

- Dockerで安定起動する
- API経由でデータを登録できる
- WordPressから同期できる
- データ履歴が残る
- JSONLを入出力できる
- 画像・音声などのアセットを管理できる
- データを検索できる

### 第二段階：品質管理

```text
候補
→ レビュー待ち
→ 承認
→ 学習利用
→ 評価
```

以下を分析可能にする。

- どのデータが性能改善に寄与したか
- どのデータが誤答を増やしたか
- どの生成モデルのデータ品質が高いか
- どのカテゴリーのデータが不足しているか

この段階では、データ数よりもデータの有効性を測定できることを重視する。

### 第三段階：知識変換

1つの入力から、用途の異なる成果物を生成できるようにする。

```text
文章
├── LLM用Instructionデータ
├── Q&Aデータ
├── DPOデータ
├── SARAイベント列
├── 概念
├── 実体
├── 関係
└── 出典情報
```

登録した情報を用途ごとに何度も作り直さず、Knowledge Serverを知識変換基盤として利用できる状態を目指す。

### 第四段階：経験からの構造形成

複数の観測から関係候補を形成する。

```text
ベルが鳴った
→ 食事が出た
→ ベルが鳴った
→ 食事が出た
```

この反復から、以下のような関係候補を生成する。

```text
ベル --predicts--> 食事
```

関係には証拠数、反例数、確信度、時間差、有効期間、文脈を保持する。この段階に到達すると、システムはデータ管理を超え、限定的ながら経験から構造を形成する。

### 第五段階：構造共有からの未知関係生成

複数の具体例から再利用可能な構造パターンを抽出し、新しい事例へ適用する。

```text
既知の複数構造
→ 共通パターン
→ 新しい事例への変数割当
→ 未保存relationの候補生成
→ 根拠・反例・文脈を含む検証
```

保存済みrelationの検索ではなく、held-out relationを構造から候補生成できることを成功条件とする。推論候補と検証済み事実は分離し、導出経路を再現可能にする。

具体経験を共通Structure＋型付きDeltaとして決定的に再構成でき、複数Deltaから再利用可能なTransformation Patternを抽出できることも評価対象とする。圧縮率だけでなく、例外保持率、復元成功率、変換による予測改善を同時に満たす必要がある。

さらに、人間定義の分類や全グラフ同型判定だけに依存せず、局所Unitの再利用から名前のない共有構造を形成できることを研究目標とする。そのUnitは頻出であるだけでは不十分で、held-out予測、別文脈への転移、圧縮、検索のいずれかを改善し、出典と反例へ戻れる必要がある。

構造候補は、独立した知的Verifierだけでなく、予測誤差、分岐競合、恒常性、Replayを用いて低コストに選別できることを目指す。ただし動的安定性を真実と同一視せず、外部検証状態と分離する。環境変化に適応しながら、少数例と反例を保持できることを成功条件に含める。

### 第六段階：クロスモーダル構造転移

文章、映像、音・音楽、触覚のnative valueと固有residualを保持しながら、一つのモダリティで得たFactorを別のモダリティへ適用する。

```text
Source modalityのStructure
→ cross-modal Factor候補
→ Target modalityへのbinding
→ Targetのheld-out予測・再構成・行動
```

表面波形、Embedding、収録時刻が似るだけでは成功とみなさない。Target modalityだけで学習したbaselineより予測または制御を改善し、hard negative、alignmentずれ、dataset leakageへの耐性を示し、元観測・segment・出典・residualへ戻れることを成功条件とする。

### 最終段階：持続的なAI記憶

SARAや他のAIがKnowledge Serverを使うことで、モデル単体や通常のRAGよりも次の点で優れることを目指す。

- 長期的一貫性
- 知識の修正可能性
- 出典の追跡可能性
- 個人・プロジェクトへの適応
- 過去の経験の再利用
- 継続的な知識更新
- 回答根拠の説明可能性

## 比較評価

以下の3構成を同じ課題で比較する。

```text
LLM単体
LLM + 通常のRAG
LLM + SARA Knowledge Server
```

Knowledge Server構成が、正確性、一貫性、修正容易性、追跡可能性で優位になることを示す。

## 失敗の兆候

以下は成功とはみなさない。

- 大量保存できるが実際には使われない
- 関係が増えすぎて検索できない
- LLM生成の誤情報を無検証で蓄積する
- WordPressとPostgreSQLが同時に正本になる
- データ構造が複雑すぎて人間が管理できない
- 概念・関係形成のコストが効果を上回る
- 通常のRAGと性能差がない
- 個別関係を保存するだけで、未保存関係を生成できない
- 構造共有が誤情報を無制限に波及させる
- 自己組織化Unitが収集元や形式などの交絡だけを表現する
- 共有表現が一つへ潰れる、または経験ごとに過剰分裂する
- 動的に安定していることを理由に誤情報を確定知識へ昇格する
- 頻出構造が例外・少数例・環境変化を消す

保存量そのものを目的にせず、必要な知識を必要な場面で正しく取り出し、修正可能な形で利用できるかを評価する。

## SARAとの関係

SARAが新しいモデルへ変化しても、これまで蓄積した経験と知識を失わないことが重要な成功状態である。

研究上は、外部化された記憶と構造学習によって、モデル単体では得られない継続性を実証することを最大の成果とする。
