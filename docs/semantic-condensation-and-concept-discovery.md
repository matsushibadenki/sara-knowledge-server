# 多様な表現からの概念抽出と再探索

更新: 2026-09-06。ユーザー提供の対話にある「未分知」「概念圧」「意味凝縮」「概念解像度」「語彙地平線」「知能複利」を、実験可能な仕組みに翻訳する。これらは対話内の呼び名であり、学術用語としての確立や語の新規性を確認したものではない。本書は設計・研究提案で、実装済み機能ではない。

## 採用する考え方

**多様な記述から再利用可能な構造候補を作り、その候補で別の記録を探索し直す。候補が実際に役立った場合だけ、概念資産として維持する。**

文章量を軽視しない。表現の違い、状況の違い、例外が増えることは、共通部分と適用境界を調べる材料になる。ただし、同じ記述の複製・翻訳・AIによる言い換えは、独立した現実の観測が増えたこととは区別する。生成例も比較・境界試験・訓練候補に利用できるが、独立証拠として加算しない。

本機構で先に目指すのは、外部の概念ライブラリによる検索・比較・推論支援の改善。DBに言葉を登録しただけでLLMの重みが学習されたり、一般知能が上がったりするとは扱わない。重みへの学習は別のDataset／Training Runで検証する。

人類史を文章量だけで説明する仮説、知能を記憶量等の積で表す式、新語数を知能の指標にする主張は、実装の前提にしない。組合せ数が増えても有用な関係が増える保証はなく、探索費用も増える。

## 既存設計への追加点

[遅延ラベリング](late-labeling-and-emergent-concepts.md)の「構造を先に、名称を後に」、[構造共有](structural-knowledge-emergence.md)の「共通パターンを別事例へ適用」、[共有表現](self-organizing-shared-representations.md)の「共通部分と固有残差」を利用する。新しい巨大な認知層を増設するのではなく、文章からの入口と比較実験を具体化する。

| 対話の観念 | 仕組みへの対応 | 判定の材料 |
| --- | --- | --- |
| 未分知 | 既存概念では説明しきれない記録群を探索候補として保持 | 繰り返す説明残差、検索失敗、境界の混同 |
| 概念圧 | 候補を調べる優先度を決める診断情報 | 独立由来の多様性、既存表現の複雑さ、改善余地、探索費用 |
| 意味凝縮 | 共通する役割・条件・状態変化を抽出 | 共通構造＋適用条件＋例外で記録を説明できるか |
| 概念解像度 | 用途に応じた概念の分割・統合候補 | 過剰統合・過剰分割、未知事例の判別誤り |
| 意味発芽・語彙地平線 | 新候補で過去の別記録を再探索 | 従来検索で拾えなかった適合例・反例を見つけるか |
| 知能複利 | 概念の再利用で次の課題の費用が下がるかを測る | 同じ予算での正答・検索精度・解決時間の推移 |

「概念圧」を真偽判定用の単一スコアにしない。探索優先度と証拠の確かさを別々に記録し、最初は成分別の比較を行う。

## 処理の循環

```text
版を固定したRecord／Eventの集合
→ 由来をまとめ、表現・文脈の多様性を計測
→ 既存概念で説明しにくい局所群を取得
→ 名前なしの構造候補と適用条件を生成
→ 既存概念・類義語・反例と比較
→ 未使用の評価データで候補あり／なしを比較
→ 有用な候補をレビューし、必要なら三言語で命名
→ 上限付きで別の記録を再探索
→ 適合例・反例・訂正を記録し、再評価
```

1. **由来の分離:** 原観測、引用、翻訳、要約、生成言い換えの関係を保持する。同じ元資料の100例を100独立証拠としない。由来が不明なら独立性不明とする。異なるドメイン名だけで独立と判定しない。
2. **候補の取得:** 字句／Embedding検索と局所Relationから候補群を作る。類似度は入口であり、同一概念・因果性の証拠ではない。否定、役割逆転、時点差を残す。
3. **構造の提案:** 名前より先に、役割変数、成立条件、適用不能条件、期待される帰結、観測へのbindingを記録する。共通部分だけで説明できない値はresidualとして元記録に残す。
4. **既存概念との照合:** 言語をまたいで定義・例・反例を比較し、同義ならAlias候補、特殊条件なら下位概念候補、同一性不明なら保留とする。「調べた語彙内で未一致」と「人類未発見」を区別する。
5. **独立した検証:** 候補生成に使っていないSource群・文脈で、検索や判別への効果を測る。生成モデルの自己採点だけで合格させない。少数例・hard negativeの誤用も確認する。
6. **名前と採用:** 安定IDと概念revisionに対して日本語・English・简体中文の定義／Aliasを付ける。翻訳の意味が一致しない場合はscopeを分ける。命名、タスクでの有用性、個々の主張の事実確認を別の判断にする。
7. **再探索:** 全コーパス総当たりは行わず、候補ごとのtop-k・時間・token・連鎖深度を固定する。再探索による新Relationもproposal扱いとし、既存知識を自動上書きしない。

再探索された元記録は独立証拠として新たに数え直さない。候補から作った説明文・仮想例・その派生候補には生成系譜を伝え、元候補を循環的に支持することを防ぐ。候補生成・適用の系譜はDAGとして扱い、一般の知識Relationの循環とは分ける。

## プロジェクト内の具体例

次の3種類の記述を比較する。

- 文書を訂正したが検索cacheが古いままだった。
- Recordを更新したが依存Relationは以前の判断を保持した。
- Datasetに使った証拠が撤回されたが、利用者には影響が見えなかった。

候補構造は「根拠Aに依存する成果物Bについて、Aの変更後にBの利用条件を再評価する必要がある」。これは既存の依存関係管理・無効化という概念で説明できる可能性が高いため、新語の発見として数えない。それでも3領域を同じ検索・レビュー観点で扱えるなら、概念の再利用として価値がある。

反例は「過去時点を再現する不変Snapshot」。原本更新に合わせてSnapshot本文を書き換えると再現性を壊す。従って共通化するのは『成果物をすべて最新化する』ではなく『現在利用への影響を判定し、過去利用の根拠を保持する』という条件付き構造になる。この境界を発見・保持できるかが概念の品質になる。

## 保存と実行の責務

最初の実験はリポジトリ内の研究用JSONL等で行い、本番migrationや自動採用APIを追加しない。研究出力にも元のRecord Version／Snapshot参照とhashを保持する。既存Concept／Evidenceだけで完全な版固定ができるとは仮定せず、G0／G1完了後に連携を設計する。

| 論理的な保存単位（table名ではない） | 最小情報 |
| --- | --- |
| 原記述と派生表現 | source revision、record version、segment、language、origin group、derived-from、生成器版 |
| 候補と改訂 | candidate ID／revision、構造、条件、例外、既存概念との差分、入力Snapshot、生成元 |
| 適用記録 | 候補revision、対象revision、role binding、residual、支持／反例／不明 |
| 評価とレビュー | task／split／policy版、比較構成、指標、費用、判断者、結果 |
| 再探索Run | 親候補revision、探索対象Snapshot、budget、seed、結果、停止理由 |

候補の状態案は proposed → evaluated → accepted-for-task／rejected／dormant。accepted-for-taskは特定タスクでの採用であり、現行APIのverifiedへ直結させない。名前の変更と構造の変更も分離する。

候補の根拠が訂正・撤回されたら依存先をstaleとし、再評価する。分裂・統合は新revisionと対応関係で追跡し、過去の利用traceは当時の版を参照し続ける。Sourceの権限境界は抽出・候補共有・再探索でも保持する。

候補生成と評価は交換可能なWorker／Engineが担当し、Knowledge Serverは根拠・revision・判断・利用履歴を保存する。本番連携時も通常VPS WorkerはCloud側のHTTPS APIを使い、Managed PostgreSQLへ直接接続しない。

## 小規模実験 SC-0〜SC-2

以下は未実施。DB製品のG0修復を延期しない独立した研究trackとする。

- [Later] **SC-0: 量と多様性の切り分け。** 同じ入力token予算で、A:元記録の単純反復、B:同じ元記録の意味を確認した言い換え、C:異なる文脈の独立事例、を比較する。別に文脈分布を揃えた入力token数の増加実験を行う。量の効果と由来・文脈多様性の効果を分けて報告する。
- [Later] **SC-1: 概念の効果。** 同じ固定モデルで、通常RAG、既存概念で整理したRAG、名前なしの構造候補を加えたRAG、名称だけ加えた対照を比較。候補定義・例・生成費用もcontext／計算予算に含める。
- [Later] **SC-2: 再探索の効果。** 一回抽出と上限付き2巡の再探索を同じ総予算で比較し、新しい適合例だけでなく反例の発見と回帰を測る。

最初は1領域、30以上の原資料群、300以上の記述を目安とする。三言語の翻訳・言い換えは必ず同じorigin group／splitにまとめる。これは必要十分な標本数の主張ではなく実装可能性を見る初期規模。概念発見用・開発評価用・最終held-outをSource群で分け、最終held-outは抽出・再探索・閾値調整に使わない。

概念候補は1 Run最大20件、候補ごとに再探索100記録、深度2、最大2巡を初期上限とする。token／時間／費用上限は実験開始前にmanifestへ固定する。上限到達、改善なし、反例違反の増加で停止し、停止理由を記録する。限られた候補の不合格から観念全体が不可能とは判断しない。

**主指標:** 未知文脈の検索Recall@10、根拠付き判別精度、hard negativeの誤適用率、反例保持、1問あたり費用。圧縮は候補定義・binding・例外の表現費用込みで比較し、名称への置換だけで圧縮成功としない。

**採否:** 最も強いbaselineと同じ予算で、事前指定した主指標が改善し、根拠追跡と反例保持が損なわれないこと。言語別・origin group別にpaired結果と不確実性を報告する。初期標本で判定困難なら優位性未確認とする。concept数、名前の面白さ、生成文章量だけでは採用しない。

## 研究上の根拠と限界

再利用可能な抽象を獲得し、後続の問題解決へ使う方向には先行研究がある。[DreamCoder](https://arxiv.org/abs/2006.08381)はプログラム学習で抽象のライブラリを拡張する仕組みを扱う。ただし、自然言語コーパスから汎用的な新概念を発見する本提案の成功を証明するものではない。

生成データの再帰的な学習には、条件によって分布の劣化が起こる研究結果がある。[Shumailov et al., Nature 2024](https://www.nature.com/articles/s41586-024-07566-y)。これは生成文の利用をすべて否定する結果でも、重み学習を伴わないDB再探索で必ず同じ現象が起きる証明でもない。本提案ではその結果と別に、証拠の独立性と循環的な自己正当化を管理する。参照確認: 2026-09-06。

## English summary

Extract reusable, conditional structures from diverse descriptions, then use them to search other records under a fixed budget. Track original observations separately from copies, translations, and synthetic paraphrases. Test structures against existing concepts and held-out counterexamples before naming or adoption. Evaluate task benefit, not concept count. Keep this research separate from G0 database repairs; no runtime or schema is added by this document.

## 简体中文摘要

从多种表述中提取带适用条件的可复用结构，再在固定预算内重新检索其他记录。区分原始观察、复制、翻译和生成式改写，并保留来源关系。命名或采用之前，必须与既有概念及未参与生成的反例比较。以任务效果而非概念数量评价价值。本研究独立于G0数据库修复，本文件不新增运行功能或数据库表。
